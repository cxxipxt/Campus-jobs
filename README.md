# DATABASE_README

เว็บไซต์จัดหางานพาร์ทไทม์สำหรับนักศึกษา เชื่อมต่อนักศึกษาที่กำลังหางานกับนายจ้างที่ต้องการรับพนักงาน พร้อมระบบประกาศงาน สมัครงาน และติดตามผลการสมัคร

คู่มือภาพรวมโครงการ การแบ่งงาน และการเตรียมฐานข้อมูลสำหรับทีม **โอปอ มิก และเตอร์**

---

## 1. ภาพรวมโครงการ (Project Overview)

ระบบมีผู้ใช้งานหลัก 2 บทบาท โดยใช้โครงสร้างฐานข้อมูลเดียวกันเพื่อให้ทีมพัฒนาแต่ละส่วนและนำมาเชื่อมกันได้

### นักศึกษา (Student)

- สมัครสมาชิก เข้าสู่ระบบ และออกจากระบบ
- จัดการโปรไฟล์ มหาวิทยาลัย สาขา ทักษะ และลิงก์ Resume
- ค้นหางาน กรองประเภทงาน สถานที่ และค่าจ้างต่อชั่วโมง
- ดูรายละเอียดและบันทึกงานที่สนใจ
- สมัครงาน ดูประวัติ และติดตามสถานะใบสมัคร

### นายจ้าง (Employer)

- สมัครสมาชิก เข้าสู่ระบบ และจัดการข้อมูลบริษัทหรือร้านค้า
- สร้างและแก้ไขประกาศงาน ระบุประเภทงาน ค่าจ้าง เวลางาน และทักษะที่ต้องการ
- เปิดหรือปิดรับสมัครงาน
- ดูโปรไฟล์ ทักษะ และลิงก์ Resume ของผู้สมัครในงานของตนเอง
- พิจารณาและเปลี่ยนสถานะใบสมัคร

เวอร์ชันแรกยังไม่รวมแชต ชำระค่าจ้าง รีวิว อัปโหลดไฟล์ Resume จับคู่งานอัตโนมัติ แจ้งเตือนอีเมล/SMS และหน้าผู้ดูแลระบบ ดูรายละเอียดใน [ขอบเขตระบบ](docs/scope.md)

## 2. สถานะและเทคโนโลยี (Project Status & Technology)

| รายการ | สถานะ |
|---|---|
| ขอบเขตและแผนแบ่งงาน | มีเอกสารแล้ว |
| ER Diagram และ Data Dictionary | เตรียมไว้แล้ว |
| ฐานข้อมูล | MySQL 8.0.16 ขึ้นไป / InnoDB / utf8mb4 |
| SQL โครงสร้าง | มี `schema.sql` ครบ 8 ตาราง |
| ข้อมูลเริ่มต้น | มีประเภทงาน 7 รายการใน `seed.sql` |

| การทดสอบ SQL กับ MySQL จริง | ยังไม่ได้ดำเนินการในเครื่องที่จัดทำไฟล์ |

ปัจจุบันเป็นชุดเอกสารและโครงฐานข้อมูล ยังไม่มีเว็บไซต์ที่รันได้ MySQL ต้องเป็นเวอร์ชัน 8.0.16 ขึ้นไปเพื่อบังคับ `CHECK` constraints หากใช้ XAMPP ให้ตรวจว่าเซิร์ฟเวอร์เป็น MySQL หรือ MariaDB ก่อนนำเข้า

## 3. การแบ่งงานทีม (Team Responsibilities)

แต่ละคนดูแลหน้าเว็บ Backend และการเชื่อมฐานข้อมูลของฟีเจอร์ที่รับผิดชอบ โดยใช้โครงสร้างฐานข้อมูลเดียวกัน

| ผู้รับผิดชอบ | ฟีเจอร์ที่ดูแล | ตารางหลัก |
|---|---|---|
| **โอปอ** | สมัคร/ล็อกอินนักศึกษา โปรไฟล์ ทักษะ และลิงก์ Resume | `STUDENT`, `STUDENT_SKILL` |
| **มิก** | สมัคร/ล็อกอินนายจ้าง ข้อมูลบริษัท ประกาศงาน เปิด/ปิดงาน และทักษะที่ต้องการ | `EMPLOYER`, `JOB_CATEGORY`, `JOB`, `JOB_SKILL` |
| **เตอร์** | ค้นหา/กรอง/ดูงาน บันทึกงาน สมัครงาน ประวัติ และหน้าพิจารณาใบสมัครของนายจ้าง | `APPLICATION`, `SAVED_JOB` |

โอปอรวบรวมเอกสารและประสานทดสอบรวม มิกเตรียมประกาศและประเภทงานตัวอย่าง เตอร์เชื่อมเส้นทางค้นหา สมัคร และติดตามผล หากต้องย้ายหน้าพิจารณาใบสมัครให้มิก ให้ตกลงร่วมกันก่อน

อ่านรายละเอียดใน [แผนแบ่งงาน](docs/team-plan.md) และ [แนวทางเชื่อมข้อมูลของทีม](database/team-guide.md)

## 4. โครงสร้างฐานข้อมูล (Database Design)

Conceptual ER มี 5 Entity หลัก ได้แก่ STUDENT, EMPLOYER, JOB_CATEGORY, JOB และ APPLICATION เมื่อแปลงเป็นฐานข้อมูลจะมี 8 ตาราง โดยแยกทักษะและความสัมพันธ์บันทึกงานเพิ่มเติม

| ตาราง | หน้าที่ |
|---|---|
| `STUDENT` | บัญชีและโปรไฟล์นักศึกษา |
| `STUDENT_SKILL` | ทักษะของนักศึกษา หนึ่งทักษะต่อแถว |
| `EMPLOYER` | บัญชีและข้อมูลนายจ้าง |
| `JOB_CATEGORY` | ประเภทงานที่กำหนดไว้ล่วงหน้า |
| `JOB` | ประกาศงานของนายจ้าง |
| `JOB_SKILL` | ทักษะที่แต่ละประกาศต้องการ |
| `APPLICATION` | ใบสมัครและสถานะการพิจารณา |
| `SAVED_JOB` | งานที่นักศึกษาบันทึกไว้ |

### กฎสำคัญ

- งานมีสถานะ `Open` หรือ `Closed` ค่าเริ่มต้นคือ `Open`
- ใบสมัครมีสถานะ `Pending`, `Reviewing`, `Accepted` หรือ `Rejected` ค่าเริ่มต้นคือ `Pending`
- นักศึกษาสมัครประกาศเดียวกันซ้ำไม่ได้ และบันทึกงานเดิมซ้ำไม่ได้
- ค่าจ้างต่อชั่วโมงต้องไม่ติดลบ
- ใช้ Foreign Key เชื่อมข้อมูลและป้องกันการลบข้อมูลที่ยังถูกอ้างอิง
- เก็บเวลาเป็น UTC และแสดงผลในเขตเวลา `Asia/Bangkok`
- Backend ต้องตรวจเจ้าของข้อมูลและสถานะเปิดรับงานก่อนสมัคร

ดู [Data Dictionary](database/data-dictionary.md) และดาวน์โหลด [ER Diagram แบบ Chen](docs/erd/campus-jobs.drawio) เพื่อเปิดใน draw.io

## 5. การติดตั้งฐานข้อมูล (Database Setup)

### สิ่งที่ต้องเตรียม

- MySQL Server 8.0.16 ขึ้นไป
- MySQL Workbench หรือ mysql command-line client
- Git สำหรับรับและส่งงานร่วมกัน

### ขั้นตอนติดตั้ง

1. ทุกคนสร้างฐานข้อมูลพัฒนาบนเครื่องตัวเองด้วยโครงสร้างเดียวกัน
2. สร้างฐานข้อมูลใหม่ที่ยังว่างและเลือกใช้งาน:

   ```sql
   CREATE DATABASE campus_jobs
       CHARACTER SET utf8mb4
       COLLATE utf8mb4_unicode_ci;
   USE campus_jobs;
   ```

3. ใน connection เดิม รันไฟล์ตามลำดับ:

   | ลำดับ | ไฟล์ | ผลลัพธ์ |
   |---|---|---|
   | 1 | [schema.sql](database/schema.sql) | สร้าง 8 ตาราง รันครั้งเดียว |
   | 2 | [seed.sql](database/seed.sql) | เพิ่มประเภทงานเริ่มต้น รันซ้ำได้ |
   | 3 | [verify.sql](database/verify.sql) | ตรวจโครงสร้างโดยไม่แก้ข้อมูล |

4. ตรวจว่าพบ 8 ตาราง, 8 Foreign Key, 16 CHECK constraints ที่บังคับใช้ และประเภทงาน 7 รายการ
5. ให้ Backend ตั้ง `SET SESSION time_zone = '+00:00';` ทุก connection ก่อนอ่านหรือเขียนเวลา

`schema.sql` ใช้กับฐานข้อมูลใหม่ที่ยังว่าง หากมีตารางเดิมหรือเกิดข้อผิดพลาดให้หยุดและตรวจสอบก่อนรันต่อ ดูคำสั่ง mysql client และข้อกำหนดเพิ่มเติมใน [คู่มือติดตั้งฐานข้อมูล](database/README.md)

## 7. วิธีทำงานร่วมกัน (Development Workflow)

1. ตกลงภาษา Backend โครงสร้างไฟล์ ระบบ Session และหน้าตาเว็บร่วมกัน
2. ทุกคนติดตั้งฐานข้อมูลจาก `schema.sql` และ `seed.sql` ชุดเดียวกัน
3. แยก branch เช่น `feature/student`, `feature/employer` และ `feature/applications`
4. พัฒนาและทดสอบส่วนที่รับผิดชอบ ก่อนเปิด Pull Request ให้เพื่อนตรวจอย่างน้อย 1 คน
5. หลังรวมงาน ทุกคนดึง `main` ล่าสุดและทดสอบเส้นทางร่วมกัน
6. หากต้องเปลี่ยนโครงสร้างฐานข้อมูลหลังเริ่มใช้งาน ให้ตกลงร่วมกันและเพิ่ม migration ตามลำดับ

ใช้ข้อมูลสมมติสำหรับทดสอบ สร้างบัญชีทดลองผ่านระบบที่แฮชรหัสผ่านจริง และเก็บค่าการเชื่อมต่อส่วนตัวใน `.env` ดูรายละเอียดใน [CONTRIBUTING](CONTRIBUTING.md)
