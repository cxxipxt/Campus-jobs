# แบ่งงานทีม 3 คน

มิก (`@cxxipxt`) คือเจ้าของ repository และผู้ตรวจ Pull Request ก่อนรวมงาน
การแบ่งหน้าเว็บล่าสุดอยู่ใน [frontend/README.md](../frontend/README.md) ตารางด้านล่างเป็นแผนฐานข้อมูลเดิม
อ่านวิธีสร้าง branch และส่งงานใน [GitHub workflow](github-workflow.md)

แต่ละคนทำทั้งหน้าเว็บ backend และการเชื่อมฐานข้อมูลในส่วนที่รับผิดชอบ ใช้ฐานข้อมูลโครงสร้างเดียวกัน ทุกคนอ่านตารางข้ามส่วนได้

| ผู้รับผิดชอบ | ฟีเจอร์ | ตารางที่ดูแล |
|---|---|---|
| โอปอ | สมัคร/ล็อกอินนักศึกษา โปรไฟล์ ทักษะ ลิงก์ Resume | STUDENT, STUDENT_SKILL |
| มิก | สมัคร/ล็อกอินนายจ้าง ข้อมูลบริษัท สร้าง/แก้ไข/เปิดปิดงาน ทักษะที่งานต้องการ | EMPLOYER, JOB_CATEGORY, JOB, JOB_SKILL |
| เตอร์ | ค้นหา/กรอง/ดูงาน บันทึกงาน สมัคร ประวัติ และหน้าพิจารณาใบสมัครของนายจ้าง | APPLICATION, SAVED_JOB |

เตอร์ มีงานหลายขั้นตอน หากงานมากให้ตกลงย้ายหน้ารายชื่อผู้สมัครและเปลี่ยนสถานะให้มิก ก่อนเริ่ม ไม่เปลี่ยนผู้รับผิดชอบเงียบ ๆ
โอปอรวบรวมเอกสารและประสานทดสอบรวม มิก เตรียมประกาศและประเภทงานตัวอย่าง

## งานร่วมก่อนแยกทำ
- ยืนยันเทคโนโลยีและโครงสร้างไฟล์
- เลือกผู้ดูแล schema กลาง (ยังไม่ระบุบุคคล)
- ตกลงชื่อฟิลด์ สถานะ วิธีตรวจล็อกอินและบทบาท
- ตกลงเมนู สี และองค์ประกอบหน้าเว็บร่วมกัน
- เก็บงานเป็น branch: feature/student, feature/employer, feature/applications หรือแยกย่อยตามฟีเจอร์

## ลำดับพัฒนา
1. ฐานข้อมูลร่วม + บัญชีผู้ใช้ + ข้อมูลตัวอย่าง
2. โปรไฟล์และประกาศงาน (ทำคู่ขนานได้)
3. ค้นหา บันทึก สมัคร และพิจารณาใบสมัคร
4. ทดสอบเส้นทางครบตั้งแต่ประกาศจนดูผล และเตรียมสาธิต

## งานถือว่าเสร็จเมื่อ
หน้าเว็บเชื่อมข้อมูลจริง ตรวจสิทธิ์และข้อมูลผิดพลาดได้ ทดสอบตาม scope แล้ว และมีเพื่อนตรวจ PR
